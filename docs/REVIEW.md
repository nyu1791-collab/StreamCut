# 実装後の見直しと確認状態

2026-10-24。実装を一度組み立てた後に、工程の重複、時刻、分担、再開、公開する情報を見直した。

## 見直して修正した点

| 問題 | 修正 |
|---|---|
| ローカルにGPU4枚ある前提ではColabに合わない | 共有フォルダと固定rankへ変更。GPU1〜4、CPU1〜4を起動前に指定する |
| 任意時刻のcopy取得を精密と扱うと原点が曖昧になる | 初版は動画を一度保存し、同じ動画からalignment用音声と最終映像を作る。部分映像取得は見送った |
| フレーム格子と字幕の秒数を別々に計算するとずれる | `keep_frames`を共通化し、映像・音声・字幕を同じ区間表へ従わせた |
| alignmentで時刻のない文字が消える可能性 | 本文を検査し、数字・固有名詞の欠損時刻は補間・警告。編集で単語が削除区間をまたぐ場合や完全に消える場合は停止する |
| ASRとalignmentのモデルを同時保持するとVRAMを使う | alignment開始前にASRを解放。単一ランタイムでは描画前にalignmentも解放 |
| 字幕や見出しの調整で全文ASRをやり直すのは無駄 | `export`を追加。保存したalignmentを使い、元成果物を保持して別フォルダへ再描画する |
| 完了フラグだけでは成果物の変更を見逃す | 完了済みの再開でも元動画と出力receipt・ファイルハッシュを検査する |
| 待機中に完成したMP4を何度も全読みしてしまう | 結果は一度検証したら、その待機中は再ハッシュしない |
| 異なるコードのワーカーが混在する可能性 | ワーカー自身のPythonソースのハッシュをcoordinatorと比較する |
| ワーカーの失敗で他の処理が待ち続ける | エラーreceiptを伝播し、coordinatorがfailedを記録。待機ワーカーも失敗として終了する |
| API失敗で自動再試行すると追加利用が発生する | 呼び出し前に送信状態を保存し、自動再送を禁止。明示的な`--resume`時だけ再送し得る |
| 私有データを公開コードへ混ぜる可能性 | 新しい作業フォルダに内容を除外する`.gitignore`も生成。ノートブックには実行結果を保存せず、秘密値はColab Secrets／環境変数を使う |
| 同名出力へ二重に移動するとフォルダが入れ子になる | クリップ確定時は同じファイルシステム上のrenameで確定し、既存の異なる成果物を上書きしない |

## 実施した確認

ローカルのPython 3.12環境で **31テスト通過**。Ruff・wheel/sdist構築も通過した。GitHub ActionsではPython 3.11/3.12の検証を定義している。

- オフライン・合成素材のテスト。APIはモック、ASR/alignmentは保存済み時刻かモック。
- 実FFmpegによるMP4生成、無音カット、ASS焼き込み、SRTの時刻変換、全復号。
- 非キーフレームの開始時刻から切り、出力先頭が指定の元フレームに最も近いことを実画像差で確認。
- 音声開始を0.4秒遅らせた動画で、抽出WAVにも開始の遅れが保たれることを確認。
- 分割したPCMを連結すると、元のPCMとサンプル単位で一致することを確認。
- 30000/1001fpsの区間計算で、フレーム数の合計と出力尺が一致することを確認。
- 2GPU役・2CPU役、および4GPU役・4CPU役の共有フォルダ処理をスレッドで模擬し、実FFmpeg描画まで完了。これはColab実機での同時実行試験ではない。
- エラーreceipt、キャッシュ改変、未知のunit ID、重複選定、非有限時刻、パス逸脱、ASSの制御記法の扱いを確認。
- 同じAPI応答を再利用して再送しないこと、HTTP 429後に自動再送しないこと、途中で切れた応答を採用しないことをモックで確認。
- 保存済みalignmentからの再書き出しで、ASR・LLMを呼ばず、元のMP4を保持することを確認。
- Ruff、Python wheel/sdist構築、CLIのdoctor、Colabノートブックの構文と保存出力が空であることを確認。
- PyPIのWhisperX 3.8.6配布wheelから、使用するload_model/transcribe/load_align_model/alignの引数を確認。実推論を実施した意味ではない。

## 未確認・残す制約

- この作業環境にはCUDA GPUがない。実WhisperX推論、数字・固有名詞・複数話者の日本語品質は未確認。
- ColabのDriveマウント、パッケージ導入、GPU4台＋CPU4台の実同時実行、GPUの実メモリ、取得を含む所要時間は未確認。
- YouTube/Twitch/Kickの実動画取得は未確認。yt-dlpの対応・認証・bot判定・JS実行環境に依存する。
- 動画を全文取得するので、入力のビットレートとDrive容量・I/Oが処理時間を支配する場合がある。
- 複数coordinatorや同じrankの二重起動は対象外。Driveの排他的ファイル作成を強い分散ロックとは扱わない。
- Colabは初回の起動・認証が必要。自動割り当ては実装せず、ノートブックには自分のランタイムを解放する設定を用意した。解放APIの実動作は未確認。
- VADは静かな見せ場や認識漏れを理解しない。採用内容とカットの自然さは人が確認する。
- 形態素の途中の分割を避ける字幕実装であり、ClipForgeの全字幕規則と同等の日本語品質は保証していない。
- ピークリミッターは実装したが、EBU R128の2パス正規化・音量の受入検査は初版で省いた。
- コード・主要ASRライブラリ・依存lockを保存した。Colabの既存パッケージやHubモデルの更新まで完全に同一になる保証はない。

自動検査合格、実GPU推論成功、人による品質確認、外部公開は別の状態として扱う。新構成の処理時間を、既存ClipForgeの実測から保証しない。
