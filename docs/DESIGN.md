# 設計の判断

## 目的

長い配信から、話題別の下書き素材を少ない操作で出す。初期の対象は日本語の横動画。GPU4枚が同じマシンにある前提ではなく、Colabの独立したGPU/CPUランタイムを扱う。

利用者の通常操作は起動・設定と出力の確認。ワーカーを起動した後は、工程ごとにCSV・SRT・動画を手渡ししない。Colabランタイムの自動確保と認証の自動化は初版から外す。

## 分担

| 工程 | 実行場所 | 計算と受け渡し |
|---|---|---|
| 入力取得・音声準備 | coordinator CPU | 共有Driveに動画を一度保存、16kHz音声を作成、分割候補付近だけVAD |
| 全文ASR | GPUワーカー | 各自の音声パートをローカル一時領域へコピーしてWhisperXバッチ処理 |
| 話題・区間・見出し | coordinator / LLM API | 文字起こしだけを送る。元時刻はIDからPythonで求める |
| 採用区間alignment | 同じGPUワーカー | ASRモデルを解放し、日本語alignmentモデルを利用 |
| 無音判定・字幕・描画 | CPUワーカー | 低音量AND非発話、同じ保持区間表で映像・音声・字幕を変換 |
| 出力確認 | 各CPU / coordinator | 実復号、尺、字幕範囲・字体・表示幅、ファイルハッシュ |

GPU4＋CPU4の場合、CPUの1つがcoordinatorを兼ねる。GPUワーカーのrankは0〜3、追加CPUのrankは1〜3。タスクindexの剰余で担当を固定する。

共有Driveは分散キューやトランザクションDBではない。複数coordinatorを同じ作業フォルダへ起動しない。ワーカー数とrankを途中で変更しない。独立したランタイムから同じrankを二重起動しない。

## 再検討して変えたこと

1. 既存ClipForgeのバッチ不採用をそのまま継承しない。新規構成では話題分割をASRセグメントの長さから独立させ、LLMの意味判断へまとめる。
2. 全文alignmentをしない。全体の話題選定と、採用区間の字幕時刻の精密化を分ける。採用総尺が入力より短いほど対象を減らせる。
3. 新しいGPUモデルや分散基盤を追加しない。WhisperXとFFmpegを中心にする。VADは既存のSileroモデルを使う。
4. Auto-EditorやLosslessCutを別工程として起動しない。keep区間を一つにし、再エンコードの回数と時刻変換の重複を減らす。
5. 最初に検討した部分映像取得は初版では見送る。任意時刻のストリームコピーを「正確」と扱わず、同じ保存動画を基準にする。代償は全動画の取得時間と共有ストレージ容量。

## 時刻の規則

- 全文ASRは元動画基準の秒数を持つ。並列パートの時刻を元に戻してからIDを付ける。
- 分割点はSileroが発話していないと判定した区間から選ぶ。適切な場所がないときは分割数を減らす。分割位置で文脈が変わるため、連続ASRと同じ認識にはならない。
- 採用区間はASR unitの外縁を使う。LLMが自由に小数秒の切断位置を作ることはない。
- 採用区間の音声は最終映像と同じ保存動画から抽出する。audio開始PTSはリサンプラーで0起点へそろえる。
- 外縁はフレーム格子の外側、削除区間は内側へ丸める。発話を狭める方向へ不用意に丸めない。
- `keep_frames`が映像、音声、SRT/ASSの唯一の編集区間表。削除した区間をまたぐ単語があると停止する。
- ASSとSRTは共通の字幕イベントを0.01秒単位にそろえて保存する。
- フレーム単位の切断精度と、人の発音を認識する精度は別。alignmentの補間箇所は警告にする。

## 再開と失敗

入力・設定・コード・取り込みファイルを識別し、同じ作業だけを再開する。各タスクは内容から作ったkeyを持ち、結果JSONと生成メディアをハッシュで検査する。

API失敗・応答不明は自動再送しない。`--resume`は明示的な再試行であり、前の応答が受け取れなかった場合には追加のAPI使用が発生し得る。

ワーカー失敗はエラーreceiptを残す。coordinatorは失敗を検知してprojectをfailedにし、他の待機ワーカーも終了する。ColabのVM解放はノートブックの設定または利用者による停止に任せる。

生成物は仮ディレクトリで完成させてから確定する。入力は上書きしない。途中成果物・字幕・ログは共有フォルダの私有データで、Gitへ入れない。

## まだ採用しないもの

自動ランタイム確保、GitHub Actions/Releaseによるメディア配送、埋め込みDB、常駐Webアプリ、顔追跡、話者分離、音源分離、視覚による盛り上がり検出、画像/BGM/チャット合成、SNS公開、smart cut、全編alignment。

日本語の全文精度、ゲームの見せ場、実際のColab速度は実素材の確認が必要。全文を取得する初版なので、3時間を何分で処理できるかは未計測。GPU4台でも起動・モデル取得・Drive I/Oは4分の1にならない。
